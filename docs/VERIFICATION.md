# 验证范围与现场验收

## 这份源码验证了什么

- Ruby 离线测试：服务器别名与 SNI、循环别名拒绝、生成幂等性、输入限制、loopback 后备、门户来源限制、双层编码、登录后验证、退避与私有文件权限。
- 本机 HTTP 集成：通过真实 curl 访问仅绑定 loopback 的假门户，校验 UTF-8 与保留字符编码，并确认错误来源不会收到登录提交。没有使用真实账户。
- Linux 新网络命名空间：建立虚构双上联，移除移动默认路由后，标记连接与固定节点连接失败；未标记的普通直连仍走校园虚构接口。所有网络修改都在新命名空间，不触碰宿主网络。
- ShellCheck 与发布目录扫描。

内核命名空间测试验证策略路由原理，没有运行 OpenWrt netifd、真实透明代理、固件防火墙或无线驱动。认证 HTTP 测试不包含真实学校的 TLS、验证码、强制踢线和门户白名单行为。

## 原始部署经历与开源版的区别

原始 TR3000 实例曾完成节点出口抓包、移动断开与恢复、Steam 下载直连等检查；也遇到过节点别名遗漏、USB 反复枚举、宽泛抓包占满临时盘等问题。

开源版从这些脚本提取逻辑，把学校、账号、节点、子网和文件位置改为配置，并加强来源与输入检查。它尚未在真实校园网重新部署验证，不能把原实例的成功记录直接算成开源版的现场测试。

## 使用者的验收清单

1. **上联与管理：** 确认校园和移动接口、网关、DNS、LAN 回程；有线管理入口可用。
2. **代理来源：** 核对完整节点配置与 `hosts` 别名；观察真实连接入口及显式 SNI，不只对旧 IP 列表抓包。
3. **规则与出口：** 分别查看应用规则、节点接口/标记、内核选路和物理接口报文。
4. **断线保护：** 在有恢复通道时断开移动上联，确认节点失败、校园直连和管理仍正常；恢复后重测。检查 loopback 不可达默认没有消失。
5. **认证直连：** 检查透明代理绕过规则，确认登录与引导 DNS 真正走校园口，再启用认证。
6. **成功含义：** 不以门户 JSON success 或单一白名单 204 当作完整联网证明；检查独立目标、响应内容与认证后地址变化。
7. **分业务：** 商店、社区、下载 CDN 和视频分片分别看，不把应用首页的路径当作所有媒体路径。
8. **持久性：** 服务重载、移动重连、正常重启和学校实际踢线后分别验证，保留明确未完成项。
9. **IPv6：** 本仓库未提供 IPv6 路由/防火墙保护，存在 IPv6 外网路径时须另行实现和验收。

抓包限定目标、接口、时间和包数，留意内核丢包与剩余空间。原始包、MAC、学校门户地址、节点 IP、账号、订阅、响应和备份只留在自己的私有位置。反馈问题时用脱敏拓扑、版本、步骤和预期/实际结果。
